The Problem

Built from a real mistake

After my first son was born in September 2025, I searched hundreds of property listings — none warned me about flood risk. I found out when rainy season arrived and the street became a pond.

📋

The problem with existing platforms

Property platforms show price, bedrooms, and photos. None surface geospatial risk data — flood zones, landslide areas, road access — the things that determine livability long-term.

🌊

The flood risk no one mentioned

The area had BNPB-classified moderate flood risk. That data existed publicly. It just wasn't connected to property search. I moved in and learned the hard way.

🗺️

A GIS engineer's frustration

I work with spatial data every day. I knew the data existed — BNPB disaster risk, BPS census, SRTM elevation, OSM facilities. None of it was connected to how people search for homes.

🤖

The solution: GeoNest

An AI agent that accepts natural language queries, runs spatial analysis against 9 real data layers, and returns ranked, risk-aware property recommendations with explainable scores.

Technical Challenges Solved

Engineering decisions

01
23,488-polygon spatial index without timeout
Iterating vertices of 23K landslide polygons per property caused n8n execution timeouts. Solved by pre-building a per-subpolygon bbox + centroid index at startup — reducing lookups from O(features × vertices) to O(subpolygons) with bbox prefilter. 2-pass: exact PIP first, then nearest-centroid fallback with 2km threshold.
Spatial indexing
02
78% of properties in polygon gaps
BNPB flood data has large spatial gaps — 78% of test properties fell outside any flood polygon. A naïve fallback to 'low' was wrong; a centroid-of-whole-feature fallback returned geographically incorrect risk. Solution: per-subpolygon centroids with a conservative 2km distance threshold — beyond 2km defaults to 'low' rather than trusting a distant polygon.
Risk classification
03
Semantic location inference
"Sunset spot" doesn't contain a place name but implies west-facing coast. "Quiet area" implies low population density. Solved at the intent parser level — Claude maps lifestyle keywords to spatial filter values (sunset → west_bali bbox, sunrise → east_bali, surfing → beach_preference: close) before the scoring engine runs.
NLP + GIS
04
Conversational memory in a stateless webhook
Each webhook call is stateless — no session memory. Follow-up questions like "what do you know about that villa?" had no context. Solved by passing last_property JSON in every request body from the frontend, and adding is_followup detection in the intent parser to skip spatial search entirely and route directly to the agent LLM.
Architecture
05
Normalising score across variable query types
When beach_preference is not requested, the beach slot (15 pts) is inactive — raw max is 85 not 100. Scores from beach and non-beach queries were incomparable. Solved by normalising: finalScore = Math.round((rawScore / maxPossible) × 100), where maxPossible is 100 or 85 depending on active slots. Score always means the same thing regardless of query type.
